## 015 · Superseding Python-port correction

The earlier review did not detect unauthorized generic recipe functionality and
must not be read as architectural acceptance. On 2026-09-21 the owner explicitly
reopened Builder JS to remove additions outside the Python port contract, keeping
version 0.1.1. No change to Python, Bag JS, publication or release was authorized.

The source audit covers every module under src, including exports and bundled
collections. This is a responsibility audit, not a proof of complete behavioral
parity. The following map identifies the reference or explicit exception:

Removed without aliases or compatibility shims:

- RecipeExpander, its export, base recipe declaration, BuilderBase.recipe and
  the special recipe Proxy branch: no generic Python counterparts.
- setData: duplicate of the existing Data Bag setItem API.
- attachSource including replace: additional root replacement lifecycle without
  a Python counterpart. bindBuilder remains the typed transport operation.
- prepareItem and the five renderer access wrappers: Python traverses children
  and reads SourceBagNode directly. Object renderers still override renderedItem
  and finalize, as in Python.
- Callable generic/argument-list descriptor acceptance: Python's JSON loader
  rejects these forms; JS now rejects them too.

Source transport, identity, object renderer, and rejected-mutation checks are
preserved. Recipe behavior tests are removed with the rejected functionality;
new checks establish absence of those APIs. The mutation-rejection case now uses
an ordinary declared leaf instead of a recipe. No unrelated failure was skipped.

Downstream Gramlot still imports RecipeExpander and uses attachSource/prepareItem.
It needs a separate consumer update; this correction does not preserve the removed
APIs to keep that consumer green. Python and JS both reject inherited declarations
when the loader has no corresponding original JSON entries; the collection conflict
remains open in both. Other missing parity remains in GBJ-020.

Verification after application to the owning repository: 100/100 tests pass on
Node 23.11.0 and Bun 1.3.14, without skips. Strict Sphinx build passes. All three
bundled JSON grammars match fresh Python exports semantically. Version remains
0.1.1. The former 103-test suite included removed recipe behavior; retained tests
were moved/adapted and absence/descriptor rejection checks were added. Counts are
not architectural acceptance. Gramlot's installed archive has not been refreshed;
consumer integration is still outstanding.

## 020 · Owner-approved Collection composition

The subsequent owner decision introduces Collection in both Python and JS. This
is an explicit addition to both implementations, not an unapproved JS-only API.
Collection stores raw JSON and metadata, merges partial declarations and exports
JSON. Builder loaders compile/validate the composition before committing state.
The previous maps of loaded documents/declarations are removed; Collection is the
single retained JSON composition. Runtime component declarations join that same
composition so a later JSON update does not discard them.

Null/omission preserves earlier values; named parameters/child rules add or update.
Removal, HTML documentation rendering, metadata extensions and replacement markers
are not implemented. Exporters keep their existing output and versions stay
unchanged. See GBJ-030 for examples and unresolved wildcard semantics.
